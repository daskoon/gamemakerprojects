✦ Building an MCP server that can completely build a GameMaker game is an incredibly ambitious and powerful idea.
  Because GameMaker projects are essentially a collection of JSON metadata files (.yy) and text files (.gml) tied
  together by a master project file (.yyp), an AI agent with the right tools can absolutely manipulate them to build a
  game from scratch.

  To achieve "complete game building," the MCP server needs to act like a headless GameMaker IDE. Here is what we would
  need to build:

  The Architecture of a GameMaker MCP

  GameMaker relies heavily on UUIDs (Unique Identifiers) to link resources. If you create an object, it needs a UUID,
  and that UUID must be registered in the master .yyp file.

  Here are the core tools our MCP server would need to expose to the LLM:

  1. Resource Generation Tools (The Core Engine)
   * create_object(name, sprite_name?, parent_name?): Generates the folder, the name.yy metadata file with a fresh UUID,
     empty event files, and registers it in the .yyp.
   * create_sprite(name, width, height, color?): Generates the sprite metadata, creates a placeholder .png frame, and
     updates the .yyp.
   * create_script(name, code): Creates a global script asset and its associated .gml file.

  2. Logic & Code Tools
   * add_object_event(object_name, event_type, code): Appends code to specific events (e.g., Create_0.gml, Step_0.gml,
     Collision_obj_wall.gml).
   * edit_script(script_name, new_code): Modifies existing script logic.

  3. Level Design Tools
   * add_instance_to_room(room_name, object_name, x, y): Parses the complex Room.yy JSON to inject a new instance layer
     entry so objects actually exist in the game world.

  4. Build & Execution
   * build_and_run(target="windows"): Hooks into GameMaker's command-line build tool (Igor.exe) to compile the project
     and launch it so you can see the results immediately.

  How We Build It

  This requires strict adherence to GameMaker's undocumented .yy JSON schemas.

  If you want to build this, I highly recommend using TypeScript/Node.js or Python. TypeScript is great because we can
  define the exact JSON structures GameMaker expects to ensure we don't corrupt the project file.
